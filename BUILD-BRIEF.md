# EDERA prototype: build brief for screen authors

Project: `~/Deropo/edera-prototype` (Vite + React 18 + TS strict + Tailwind v4 + framer-motion + lucide-react + recharts).
Dev server already running at **http://localhost:5282** (do not start another; do not stop it; `node_modules` is a symlink and must not be touched).

Product: **Edera** (brand written “e-dera.” with a brass dot), the one place for the event industry. Clients book planners, vendors and venues; the planner does most of the work; the client sees a summary from their own portal. The product's one idea, in Dave's words on the call: *“When I need a DJ, all I need to go is this place. I can see how long the DJ has been in operation, other people's reviews, and the calendar: when the day is free and when it is booked, without even contacting the DJ.”* Four platforms:
- **Client App** (`app.*`, iPhone frame): Adaeze Nwosu, London, planning her parents' ruby anniversary.
- **Planner App** (`pro.*`, iPhone frame): Tunde Bakare, Bakare Events, London & Lagos.
- **Vendor App** (`vendor.*`, iPhone frame): Bola Fashola, Ìyá Bola Catering + Olá Event Hall, Peckham (a vendor who is also a venue owner).
- **Edera Admin** (`admin.*`, MacBook browser frame): Dave, the platform owner.

Source of truth for requirements: `src/data/featureIndex.ts` (the Fiverr order request + the call, transcribed) and `src/data/screenFeatures.ts` (what each screen must demonstrate). **Read the feature entries for your screens and make sure each listed feature is visibly demonstrated on that screen.**

## Hard rules (clients have rejected builds for breaking these)
1. **No "box system".** Never more than 3 consecutive same-width/same-radius/same-elevation cards. Every screen uses ≥2 different compositional units (full-bleed photo hero, horizontal snap rail bleeding off the right edge, oversized numeral block, borderless editorial list, split panel, overlapping element, timeline spine, asymmetric bento, chart-led, the availability strip as a band). Separate with whitespace / tint / elevation / type weight, not only 1px borders. Radius hierarchy: container 24 / card 16 / control 10 / chip 999.
2. **Density.** Mobile screens ≥5 distinct component types and ≥3 richness signals (real photography doing structural work; a number with unit + comparison; a micro-chart / progress ring / strip; row metadata like timestamps, pills, avatars; a non-happy-path state visible: pending, declined, duplicate, expiring; content overflow: "+4 more", a peeking card). Primary scrolling screens scroll to ≥1.6× the frame. Lists 8–14 real items; tables 20+ rows (paginate); charts 12+ points. No lorem, no "Item 1".
3. **Legibility.** Every text ≥4.5:1 against its real background; nothing below 10px; text over photos sits on a real scrim (`HeroImage scrim="b"`). Never fade text with opacity; recede with size or weight. `text-text-2` is the only secondary colour on paper; on ink use `text-on-ink-2`.
4. **Zero typing.** Every input mounts with a value from `src/data/demoFill.ts` (`useState(DEMO_X.field)`), never `useState('')` on a required field. Every primary button works on the first tap. Validation only after an edit-to-invalid, with a visible response (toast or inline error).
5. **No dead clicks.** Every button/row navigates, opens a real overlay, mutates visible state, or fires an explicit toast via `useNav().toast(...)`. Real `<button>`s, ≥44px hit targets, `whileTap`. `onClick={() => {}}` is banned.
6. **Navigation.** `const { navigate, back, reset, toast } = useNav()`. Only registered `ScreenId`s. Before navigating to a detail screen set the store: `session.viewVendor(id)` → `app.vendor`; `session.viewThread(id)` → `app.thread`; `session.viewEvent(id)` → `pro.event`; `session.viewRequest(id)` → `vendor.request`; `session.viewCase(id)` → admin verification selection; `session.viewPlannerListing(id)`. Tab bars `reset()`; back chevrons use `TopBar` (it calls `back()`). The static link map in `src/lib/navigation.ts` (`LINKS`) lists the targets each screen may link to: use those (add to it if you need another, and tell me).
7. **Overlays.** `BottomSheet` (phone), `Modal` and `Drawer` (admin) from `src/components/Sheet.tsx`. They unmount on exit. Confirmations and detail panels go in sheets; never a bare `window.alert`.
8. **Decorative layers are `pointer-events-none`** (`aria-hidden`), including `.grain`, `.arc`, `.dots-light`, scrims.
9. **Photos** only via `img(key)` / `face(key)` / `<HeroImage src="key">` / `<Avatar who="key">` with keys from `src/data/media.ts`. Never a raw Unsplash URL.
10. **Fluid widths.** Screen roots are `w-full`, never fixed px. Rails use `Rail`. Must look right at 360–430px (phone-browser view) and in the 393px frame.

## Shared kit (use it, do not re-invent)
- Mobile shell (`src/platforms/mobileShell.tsx`): `<MobileScreen tab="…" header={<TopBar … />} dock={<Dock>…</Dock>} cap="…">`, `SAFE_TOP`, `safeTop(px)`, `safeBottom(px)`, `TABBAR_H`, `SectionHead`, `StepBar`, `Dock`. Tab ids: Client `home | explore | event | guests | inbox`; Planner `today | events | scan | calendar | proInbox`; Vendor `vToday | requests | availability | listings | account`. Full-bleed heroes may run behind the status bar (`paddingTop: SAFE_TOP` for the text, `cap="var(--night)"` so the cap fades in on scroll). `statusTone: 'light'` is set in the registry for screens that must have a dark/photo top: app.welcome, app.home, app.event, app.vendor, app.invite, pro.signin, pro.home, pro.event, pro.checkin, pro.profile, vendor.signin, vendor.home, vendor.request, vendor.listing, vendor.profile. All others have a light top.
- Admin shell (`src/platforms/console/shell.tsx`): `<ConsoleShell active="admin.x" title sub actions bleed?>` and `<Panel title action flat pad>`. Frame is 1440×820 of page minus a 248px sidebar. Use split panels, master-detail with an inspector rail, chart-led pages, a photographic or colour-block header band; not KPI row → table → card on every page. Under 768px the shell already provides app bar + drawer + tab bar; your page must reflow (tables → stacked row cards with `max-md:`; inspector → `Drawer`, which becomes a bottom sheet on phones).
- Brand (`src/components/Brand.tsx`): `Mark`, `Wordmark`, **`Strip`** (the signature: `<Strip vendor={v} highlight={RUBY.date} size="sm|md" labels />`), `StripLegend`, `StateDot`, `AvailPill`, `Money`, `Figure`, `Verified`, `Stars`, `StarRow`, `Stub` (ticket with notch), `QrCode`, `Bar`. `AVAIL` maps a state to its colours.
- Components: `Button` (accent | ink | outline | ghost | paper | danger | white; sizes sm/md/lg; `icon`, `trailing`, `block`), `IconButton`, `Pressable`, `Badge`, `Chip`, `Segmented`, `Input`, `TextArea`, `Field`, `Toggle`, `CheckMark`, `Avatar`, `AvatarStack`, `HeroImage`, `Rail`, `StatTile`, `Skeleton`, `EmptyState`, `Sparkline`, `ProgressRing`, `BarStrip`, `BudgetBar`, `CHART` (recharts styling), `Confetti`.
- Motion: `spring.ui/page/sheet/pop/frame`, `tap`, `listParent/listItem/fadeUp` from `src/motion`. Springy-overshoot: `whileTap={tap}` everywhere, staggered list entrances, `Confetti` on the big moments (booking confirmed, invites sent, verification approved).
- Type classes: `.grot` (Fraunces headings; `<em>` inside renders brass italic), `.display` (wordmark), `.label`, `.meta` (mono), `.figure` + `.unit` (big numerals), `.num`. Colours as Tailwind tokens: `bg-accent text-on-accent`, `bg-ink text-on-ink`, `bg-night text-on-night`, `bg-brass text-on-brass`, `text-brass-ink`, `text-accent-ink`, `bg-accent-soft text-on-accent-soft`, `bg-brass-soft text-on-brass-soft`, `bg-free-soft`, `bg-held-soft`, `bg-booked-soft`, `bg-danger-soft text-on-danger-soft`, `bg-info-soft text-on-info-soft`, `bg-[var(--surface)]`, `bg-[var(--surface-raised)]`, `bg-[var(--surface-high)]`, `text-text-2`. Decorative: `.arc` (brass quarter-circle, the secondary signature: put one on a hero or a success block), `.grain`, `.dots-light`, `.scrim-b`.
- Tracking: `track('intent_name', value)` from `src/lib/tracker` on meaningful actions (optional but nice).
